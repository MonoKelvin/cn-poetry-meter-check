## 1. 架构总览

分层 + 职责链，依赖方向自上而下单向：

- **数据层（data + rhyme）**：vendored 韵表 JSON → 归一化索引；RhymeTable 抽象提供“字→平仄/韵部”查询。
- **领域层（core）**：Poem / Line / Couplet / PoemChar 模型；格律谱（MeterPattern）由基本句型 + 对/粘规则生成。
- **基础检测层（modules/base）**：职责链，各检测器（平仄/押韵/替/粘/对/孤平/三平调/拗救/多音字）为最小独立单元，产出 Issue。
- **高级检测层（modules/advanced）**：对仗、多音字消歧；启发式 + LLM 两档后端。
- **推荐层（modules/recommend）**：补救/对仗/成诗/补句/填字/字眼，LLM 后端。
- **通用 AI 层（modules/ai）**：业务无关的 LLM 客户端、SKILL 装载、结构化输出解析。
- **门面（index.ts）**：对外“少而全”的 API，封装内部复杂度。

高级/推荐层依赖基础层与 AI 层；**AI 层不依赖任何诗词业务**（NFR-1 与原始需求“AI 模块业务无关”）。

## 4. 领域模型与格律谱

### 4.1 基础枚举与类型（core/types.ts）

- `Tone`：平(Level) / 仄(Oblique) / 中(Either，两可) / 未知(Unknown，韵书未录)。
- `ToneSpec`（格律谱位要求）：平 / 仄 / 中 / 平韵脚 / 仄韵脚（对应 cope 的 0–4，但以具名常量表示，不用魔法数字）。
- `PoemFormId`：`wujue`(五绝) / `wulv`(五律) / `qijue`(七绝) / `qilv`(七律)。
- `FormVariant`：起式 `ping|ze`（平起/仄起）× 首句是否入韵（boolean）。
- `RhymeBookId`：`pingshui | cilin | xinyun | tongyun`。
- `LineRole`：`chu`(出句) / `dui`(对句)。

```ts
export enum Tone { Level = 'ping', Oblique = 'ze', Either = 'zhong', Unknown = 'unknown' }
export enum ToneSpec { Level, Oblique, Either, LevelRhyme, ObliqueRhyme }
```

### 4.2 诗作模型（core/poem.ts）

- `PoemChar`：{ `char`, `index`, `resolvedTone`, `candidates`（多音字各读音的 Tone/韵部）, `rhymeGroups` }。
- `Line`：{ `index`, `role`, `chars: PoemChar[]`, `length` }。
- `Couplet`：{ `index`, `chu: Line`, `dui: Line` }——承载粘/对/对仗判定。
- `Poem`：{ `title?`, `lines: Line[]`, `couplets: Couplet[]`, `form`, `rhymeBook` }。
- 解析 `parsePoem(text)`：繁简归一（opencc 可选）→ 去标点/注释（以 `#` 起的行为注释，承 cope）→ 切句 → 构造模型。

### 4.3 格律谱生成（core/meter-pattern.ts）

不写死 16 个谱串，而由规则生成（满足“不写死”）：

1. 四个五言基本句型（见调研 §2.2）：A 仄仄平平仄 / B 平平仄仄平 / C 平平平仄仄 / D 仄仄仄平平。
2. 七言＝五言前加相反平仄的两字。
3. 据“起式 + 是否入韵”定首句，其后按 **对**（联内相反）、**粘**（联间第二字相同）逐句推导，韵脚位标记为平韵脚。
4. 产出 `MeterPattern { formId, variant, lines: ToneSpec[][] }`。

`MeterPatternBuilder` 可生成全部 16 式；校验时据文本推断诗体与变体后取对应谱比对。

## 5. 韵表设计（rhyme/）

韵表是“押韵分部”与“平仄判定”的统一数据源（FR-A9）。接口：

```ts
export interface RhymeTable {
  readonly id: RhymeBookId
  readonly name: string
  getToneInfo(char: string): ToneInfo    // 平/仄/两可/未录（+候选韵部）
  getRhymeGroups(char: string): RhymeGroup[]
  isSameRhyme(a: string, b: string): boolean
}
export interface ToneInfo { tones: Tone[]; isPolyphone: boolean }
export interface RhymeGroup { id: string; label: string; tone: Tone }
```

- **PingshuiRhymeTable**（默认）：中古音，入声归仄；数据取 `Pingshui_Rhyme.json`（上平/下平/上声/去声/入声）。
- **CilinRhymeTable**：词林正韵 19 部（填词用）。
- **XinyunRhymeTable**：中华新韵 14 韵，今音（无入声，依普通话声调分平仄）。
- **TongyunRhymeTable**：中华通韵 16 韵，今音；以 pinyin-pro 依普通话读音映射韵部与平仄（`createTongyunRhymeTable()` 异步构建后 `registerRhymeTable` 注册），无需字表。
- `registry.ts`：`getRhymeTable(id)` 工厂 + 注册，支持运行时切换与自定义注册（NFR-3）。

### 5.1 数据归一化

vendored JSON 结构各异，经 `utils/build-index` 归一为统一倒排索引：

```ts
type RhymeIndex = Map<string, { tones: Set<Tone>; groups: RhymeGroup[] }>
```

- 构建时（或首次加载懒构建）将“声部→字串”展开为“字→(声调集合, 韵部集合)”，查询 O(1)。
- 多音字判定：一个字落入多个声调或多个韵部即标 `isPolyphone`。
- 平水韵平仄兜底链：平水韵索引 → 广韵声调表（生僻/异体字，中古音同系，可直接判平仄）→ 仍无则“韵书未录”（要位提示、按通融不判错）；押韵分部仅用平水韵。
- 今音韵表（新韵/通韵）平仄由数据内置“平/仄”字段给出；缺字时回退 pinyin-pro 声调（1/2→平，3/4→仄），**仅今音韵表适用，平水韵严禁用拼音**。

## 6. 基础检测：职责链（modules/base/）

### 6.1 职责链框架

```ts
export interface Detector {
  readonly category: IssueCategory
  detect(ctx: DetectionContext): Issue[]
}
export class DetectorChain {
  constructor(private detectors: Detector[]) {}
  run(ctx: DetectionContext): Issue[] { /* 依次执行、汇总、降级 */ }
}
```

- `DetectionContext`：{ `poem`, `pattern`, `rhymeTable`, `options`, `issues`（累积，可被后续检测器读取/标注） }。
- 每个检测器职责单一、相互独立（NFR-1），可独立增删、测试、升级。
- 顺序：诗体匹配 → 平仄 → 押韵 → 替 → 粘 → 对 → 孤平 → 三平调 → 拗救（后处理，降级已救项）→ 多音字。

### 6.2 各检测器

| 检测器 | 职责 | 要点 |
| --- | --- | --- |
| FormDetector | 识别/匹配诗体与变体 | 据句数(4/8)、字数(5/7)、首句第二字与末字定起式/入韵，产出 pattern |
| PingzeDetector | 逐字平仄比对 | 遵“一三五不论”：非节奏点放宽、节奏点严格；记录出律位 |
| TiDetector | 替（句内） | 句内节奏点(2/4/6)平仄须交替（平仄平/仄平仄），违则失替 |
| RhymeDetector | 押韵 | 韵脚众数推断韵部 → 校验同部、落韵、重韵、当押未押、首句入韵 |
| NianDetector | 粘 | 联间出句与上联对句第二字平仄须相同 |
| DuiDetector | 对（平仄） | 联内出对句节奏点平仄须相反 |
| GupingDetector | 孤平 | 平收句除韵脚仅余一平 → 报（并供拗救降级） |
| SanpingDetector | 三平调/三仄尾 | 句末三连平（忌）/ 三连仄（瑕） |
| AojiuDetector | 拗救/变格 | 识别本句自救、对句相救、特拗（平平仄平仄），将相应失替/失对降级为“已拗救/变格”提示 |
| PolyphoneDetector | 多音字 | isPolyphone 且各读音影响合律 → warn，列读音/韵部/后果 |

### 6.3 关键算法要点

- **平仄比对（一三五不论）**：节奏点＝五言 2/4、七言 2/4/6 及末字，严格比对；非节奏点仅在不引发孤平/三平调时放宽。实现上先按谱标记偏离，再交由孤平/三平调/拗救检测器裁决，避免规则纠缠。
- **孤平**：仅针对平收律句（五言“平平仄仄平”、七言“仄仄平平仄仄平”）。统计除韵脚外平声数，若为 1 且关键平位被仄替代 → 孤平（默认王力说；strict 模式可启用启功“两仄夹一平”更严判定）。
- **本句自救**：孤平句第三字（七言第五字）由仄回平 → 救，标“已拗救”。
- **对句相救**：出句第四字（五言）/第六字（七言）当平而仄为大拗（须救），由对句第三字（五言）/第五字（七言）改平相救；出句第三字/第五字为小拗（半拗，可救可不救）。例「野火烧不尽（仄仄平仄仄）／春风吹又生（平平平仄平）」即出句第四字大拗、对句第三字相救。实现为“拗-救配对表”，匹配则降级。
- **特拗（变格）**：仄收句末三字作“仄平仄”（五言“平平仄平仄”、七言“仄仄平平仄平仄”）为公认变格，消除其诱发的失替/失对。
- **押韵推断**：取各韵脚字的韵部候选，按众数定全诗韵部（承 cope 思路），再逐脚校验；首句是否入韵由首句末字平仄 + 是否属该韵部判定。

## 7. 结果模型与输出（core/types.ts）

```ts
export interface Issue {
  level: 'error' | 'warning' | 'info'
  category: IssueCategory          // pingze|rhyme|nian|dui|guping|sanping|aojiu|polyphone|duizhang...
  position: { couplet: number; line: number; role: LineRole; charIndex: number; char: string }
  message: string                  // 中文描述
  suggestion?: string
  meta?: Record<string, unknown>   // 如多音字各读音
}
export interface CheckResult {
  form: { id: PoemFormId; variant: FormVariant; name: string }
  rhymeBook: RhymeBookId
  inferredRhymeGroup?: string
  passed: boolean
  issues: Issue[]
  stats: { errors: number; warnings: number; infos: number }
}
```

- 全部结果可 `JSON.stringify`，供 UI / API / LLM 消费。
- 位置以“第几联 / 出对句 / 第几字”定位（对应原始需求“颔联对句第三字”式描述）。

## 8. 高级检测模块（modules/advanced/）

API 契约固定，实现分级（启发式 / LLM），内部可留空但须返回规范结构（原始需求“保留稳定 API”）。

### 8.1 对仗检测（DuizhangChecker）

```ts
export interface DuizhangChecker {
  check(couplet: Couplet): Promise<DuizhangResult>
}
export interface DuizhangResult {
  isParallel: boolean | null       // null = 未判定/需人工
  confidence: number               // 0–1
  issues: Issue[]                   // category = 'duizhang'
  notes: string[]
}
```

- `HeuristicDuizhangChecker`（可用）：等长 + 节奏点平仄相对（可靠）＋ @node-rs/jieba 分词数/词性对应（弱信号，低可信度标注）。
- `LlmDuizhangChecker`（可选）：调 AI 模块 + `detect-duizhang` SKILL，判工对/宽对/合掌等语义层面。
- 默认对颔联、颈联执行；可配置。

### 8.2 多音字消歧（PolyphoneResolver）

```ts
export interface PolyphoneResolver {
  resolve(char: string, context: string): Promise<RhymeGroup | null>
}
```

- 后端：词表（词语→确定读音）或 LLM（`resolve-polyphone` SKILL）。
- 消歧成功则消解 PolyphoneDetector 的歧义警告，回填 `resolvedTone`。

## 9. 推荐模块（modules/recommend/）

LLM 后端，`Recommender` 门面对应 FR-C1–C6：补救、对仗替换、成诗、补句、填字、字眼。统一返回 `Recommendation[]`（文本 + 理由），多候选为列表。内部可为桩实现，返回规范结构或 `notImplemented` 标识。门面 `createRecommender({ ai, skills })` 构建：未配置 `ai` 时返回桩实现；SKILL 文本经 `loadSkillText` 读取或直接传入。大模型配置集中于本地 `cpmc.apis.json`（含密钥、已 gitignore，支持多套列表），经 `loadLlmConfigs/pickLlmConfig` 读取。

## 10. 通用 AI 模块（modules/ai/）

业务无关，仅提供对话、SKILL 装载、结构化输出三类基础能力，供高级/推荐模块调用（原始需求、NFR-1）。

### 10.1 LLM 客户端

```ts
export interface LlmClient {
  chat(messages: ChatMessage[], opts?: ChatOptions): Promise<ChatResult>
  chatJson<T>(messages: ChatMessage[], schema: ZodType<T>, opts?: ChatOptions): Promise<T>
}
export interface LlmConfig {
  provider: 'openai-compat' | 'anthropic'
  baseUrl: string; apiKey: string; model: string
  temperature?: number; timeoutMs?: number
}
```

- `OpenAICompatClient`：覆盖 OpenAI、Qwen（兼容模式）、DeepSeek、Kimi——同一 `/chat/completions` 形态，仅 `baseUrl + model + apiKey` 不同（调研 §6）。
- `AnthropicClient`：适配 `/v1/messages`、`x-api-key` + `anthropic-version`、`system` 顶层参数、content blocks、独立流式事件。
- `createLlmClient(config)` 工厂按 provider 返回实现；新增供应商只需配置（桥接，NFR-9）。
- 内置常用供应商 `baseUrl` 预设常量，调用方只填 `apiKey` / `model` 即可。

### 10.2 SKILL 装载（SkillLoader）

- 从 `skills/<name>/SKILL.md` 读取，拆解为 system 提示与规则/示例段，组装成消息。
- 支持变量注入（如待检诗句、schema），SKILL 与代码解耦、独立维护。

### 10.3 结构化输出（structured.ts）

- 可移植方案：请求 `response_format: json_object` + 提示内嵌 JSON schema；返回以 Zod 校验，失败按策略重试（调研 §6）。
- Anthropic 走工具式 / `output_config` 结构化。
- 安全：apiKey 仅由调用方运行时注入，不入库、不随包发布（NFR-10）。

## 11. 对外 API 设计（index.ts，门面）

“少而全”，隐藏内部检测器与数据细节（NFR-9、原始需求“桥接封装”）：

```ts
// 一步到位的基础检测
export function checkMeter(text: string, options?: CheckOptions): CheckResult

// 可配置的检测器（韵表、严格度、自定义检测器）
export class PoetryChecker {
  constructor(options?: CheckOptions)
  check(text: string): CheckResult
}
export interface CheckOptions {
  form?: PoemFormId | 'auto'
  rhymeBook?: RhymeBookId          // 默认 'pingshui'
  strictness?: 'strict' | 'normal' | 'loose'
}

// AI 能力（显式注入配置后才可用；SKILL 文本经 loadSkillText 读取或直接传入）
export function createAdvancedChecker(options?: {
  ai?: LlmConfig
  duizhangSkill?: string
  polyphoneSkill?: string
}): AdvancedChecker // 无 ai 时对仗退化为启发式
export function createRecommender(ai: LlmConfig): Recommender // M3
```

- 基础检测同步、纯函数式；AI 能力异步、需显式配置，默认不触网（NFR-2 / 10）。
- 仅导出门面类/函数与类型；检测器、数据索引、客户端实现不直接导出。

## 12. 常量与消息管理

- `core/constants.ts`：声调/谱位常量、诗体 id 与名称、节奏点位、默认配置、供应商 baseUrl 预设——杜绝散落魔法值（原始需求编码规范）。
- `core/messages.ts`：中文提示模板（如“{位置}失粘：…”），集中管理，统一口径并便于将来 i18n。
- 注释面向通用用途（说明 API 作用），不写特例化/调用方耦合注释（原始需求）。

## 13. SKILL 设计（skills/）

每个技能一个目录、一份 `SKILL.md`（命名统一、以目录区分，原始需求）。模板结构：

1. **角色**：精于近体诗律与对仗的专家。
2. **任务**：本技能目标（检测/推荐何物）。
3. **输入**：字段说明（诗句、诗体、韵表、上下文等）。
4. **输出 JSON schema**：严格字段定义（检测类＝问题位置+原因；推荐类＝候选列表+理由）。
5. **规则清单**：平仄/粘对/对仗（工对·宽对·忌合掌）等专业规则。
6. **正反示例**（few-shot）。
7. **参考**：王力《诗词格律》、搜韵等，必要时引导模型检索。

规划技能：`detect-duizhang`、`resolve-polyphone`、`recommend-fix-meter`、`recommend-duizhang`、`compose-poem`、`complete-line`、`fill-char`、`recommend-eye`（字眼）。

## 14. 示例页（example/）

- `index.html` + `app.js` + `app.css`，纯静态，直接打开或起本地服务即可（引用打包后的浏览器产物）。
- 功能：输入诗作、选韵表与诗体（或自动）、逐字平仄着色、错误定位标注、押韵/对仗结论；填入 apiKey 后体验高级/推荐。
- 定位为“手动验证检测结果”的工具（原始需求），不追求产品级 UI。

## 15. 测试策略（tests/）

- 框架 Vitest；覆盖每个检测器的单元测试与整体 `checkMeter` 集成测试（FR-F、原始需求“接口测试”）。
- 夹具：经典唐诗（五/七言绝句、律诗各若干），标注预期结论；来源可取自 chinese-poetry 语料（仅夹具，不入运行时）。
- 金标用例：孤平、三平调、失粘、失对（平仄）、拗救（如“野火烧不尽，春风吹又生”）、落韵、重韵、多音字歧义。
- 韵表切换：同诗以平水韵 vs 中华新韵分别校验，断言结论随韵表变化且各自自洽（FR-A9 验收）。
- 结果与权威工具（诗词吾爱 / 我爱诗词）抽样比对，纳入回归。

## 19. 风险与开放问题

- **中华通韵今音映射**：已以 pinyin-pro 依普通话生成 16 韵（声调定平仄）；韵部边界依 GF 0021—2019，个别韵母（ü 系、ueng 等）映射需复核。
- **多音字字义消歧**：字符层面不可完全消解（看/过类），依赖词表/LLM，基础层只告警。
- **对仗启发式精度**：jieba 为现代汉语训练，古诗词性/切分偏差大，词性对仗仅作低可信度建议。
- **LLM 端点/模型漂移**：model id、baseUrl 以供应商最新文档为准，集中为常量便于更新。
- **cope 复用**：cope 以 ISC 宽松许可声明（非 GPL），许可上并不限制复用；本项目不复制其源码的理由是**工程层面**（过程式、与 Electron/浏览器耦合、无对仗/拗救细分），运行数据另采 MIT 来源（charlesix59）。

## 20. 附录：数字平仄谱对照
