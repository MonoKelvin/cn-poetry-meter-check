## 1. 调研目标与方法

## 2. 近体诗格律原理

### 2.1 四声与平仄

中古汉语四声为平、上、去、入。近体诗将平声归“平”，上、去、入归“仄”。关键：须以中古音（平水韵）为准，**不能用现代普通话声调判定平仄**——因“入派三声”，古入声（仄）在今音中常读为阴平/阳平（今“平”），故今音一二声不等于古“平”。这是平仄判定必须查韵书字表、而非依赖拼音声调的根本原因。

### 2.2 基本律句（五言四式）

| 句型 | 平仄 | 名称 |
| --- | --- | --- |
| A | 仄仄平平仄 | 仄起仄收 |
| B | 平平仄仄平 | 平起平收（韵） |
| C | 平平平仄仄 | 平起仄收 |
| D | 仄仄仄平平 | 仄起平收（韵） |

七言由五言前加一组相反平仄的两字构成（如 A→平平仄仄平平仄），同样四式。

> 起式判定：平起/仄起以**首句第二字**的平仄为准（第二字为平即平起，为仄即仄起；四基本句型首二字平仄相同，故由第一字判定亦不冲突）。

### 2.3 替、对、粘（句内与谋篇）

- **替**：同一句内，节奏点（二、四、六字）平仄须逐次交替（“平仄平”或“仄平仄”）；违反即“失替”。
- **对**：同一联内，出句与对句在节奏点（二、四、六字）平仄相反；违反即“失对（平仄）”。
- **粘**：相邻两联间，下联出句与上联对句第二字（节奏点）平仄相同；违反即“失粘”。
- 由“句型 + 对 + 粘”可推导每种诗体的标准平仄谱：五绝/七绝各 4 式、五律/七律各 4 式，共 16 式。
- 例（五绝平起首句不入韵）：平平平仄仄 / 仄仄仄平平 / 仄仄平平仄 / 平平仄仄平，数字谱 `11122,22213,22112,11223`。

### 2.4 押韵

- 偶数句句末押韵、一韵到底，须同属一个平水韵部；首句可入韵（句末平声）或不入韵（句末仄声），首句入韵时可借用邻韵（“孤雁出群格”）。
- 近体诗以平声韵为常；仄韵律诗非正格，v1.0.0 以平韵为主。
- 错误类型：落韵/出韵（用了他部字）、重韵（同一字重复作韵脚）、当押而未押。

### 2.5 “一三五不论，二四六分明”

句中单数位（五言一三、七言一三五）平仄常可通融，双数位（节奏点）须严格。但此口诀有约束：不得因通融而致孤平或三平调。

### 2.6 孤平、三平调、三仄尾

- **孤平**：平收句（五言“平平仄仄平”、七言“仄仄平平仄仄平”）除韵脚外仅剩一个平声；典型为五言首字、七言第三字由平改仄（如五言→“仄平仄仄平”）。此为**王力说**，为格律检测主流所采用；另有**启功说**“两仄夹一平（仄平仄）即孤平”，可作更严格的可选判定。
- **三平调（三平尾）**：句末三字连平（如“仄仄仄平平”误作“仄仄平平平”），近体大忌。
- **三仄尾**：句末三字连仄，唐人近体亦可见，一般视为瑕疵，不如三平调严格。

### 2.7 拗句与拗救

- **拗**：不合标准平仄；**救**：在本句或对句相应位置调整平仄补偿，救后视为合律。
- 本句自救（孤平救）：五言“平平仄仄平”首字拗仄，则第三字改平→“仄平平仄平”。
- 对句相救：出句拗（如五言“仄仄平平仄”第四字拗仄→“仄仄平仄仄”），对句“平平仄仄平”第三字改平→“平平平仄平”相救。例：野火烧不尽，春风吹又生。
- 术语：出句第四字（五言）/第六字（七言）当平而仄为**大拗**（须救）；第三字（五言）/第五字（七言）为**小拗/半拗**（可救可不救）。
- 算法应识别常见拗救式并提示“已拗救”，不计为错误。

### 2.8 对仗（颔联、颈联）

- 律诗八句分四联：首联（1、2 句）、颔联（3、4 句）、颈联（5、6 句）、尾联（7、8 句）；通常要求颔联、颈联对仗，首、尾联不强制。
- 颔联、颈联对仗要求：出对句等长、词性相对、句法结构相对、平仄相对，意义相关或相对；有工对（同类工整）与宽对（大类相对）之别，并忌合掌（上下句意思雷同）。
- 纯算法可较可靠判断“等长 + 平仄相对”；词性对仗为弱信号；语义类工对、合掌须 NLP + LLM。

### 2.9 多音字

- 一字多读且平仄不同（如“长”cháng 平[七阳] / zhǎng 仄[上/去声]；“看、过、听、思、重”等）。字表层面只能给歧义警告；确切取音须结合词义/上下文，属高级检测（词表/LLM）。

### 2.10 韵表（新增需求点）

- 近体诗以**平水韵**为标准（106 部：上平 15 / 下平 15 / 上声 29 / 去声 30 / 入声 17，入声归仄）；此外有**词林正韵**（填词用，14 舒声部 + 5 入声部 = 19 部）、**中华新韵**（今音 14 韵）、**中华通韵**（教育部 GF 0021—2019，今音 16 韵）等。
- 不同韵表不仅改变**押韵分部**，也改变**平仄判定**：平水韵依中古音（入声为仄），新韵/通韵依今音（无入声，依普通话声调分平仄）。故“选韵表”须同时切换押韵分部与平仄声调两套数据。
- 需求：韵表须可切换，默认平水韵（见业务需求 FR-A9）。

## 3. 参考项目分析：cope（LingDong-/cope）

- 性质：Electron 格律诗编辑器，内置平仄/押韵/粘对/孤平/三平调/落韵检测与机器学习分析。
- 数据目录（E:\Project\cope\data）：
  - `meters.json`（1.2KB）：16 诗体键 → 逗号分隔平仄谱串，字符 0中 / 1平 / 2仄 / 3平韵脚（4仄韵脚诗中未用）。键如 `"五绝平起首句不入韵":"11122,22213,22112,11223"`。
  - `rhymebooks.json`（87KB）：键为 平水韵 / 中华新韵 / 广韵；值＝`[平组[], 仄组[]]`，每组为字符串、首字为组标签；平水韵 30 平 + 76 仄 ＝ 106 部，末 17 仄组为入声（入声保留）。
  - `ci-meters.json`（5.4KB）：57 词牌谱，出现 4（仄韵脚）。
  - `kangxi.json`（9.1MB）：字→康熙释义，无声韵字段。
  - `TC2SC.json`（40KB）：2351 繁→简映射。

- 算法要点（`src/meter.js`）：`getTonePattern` 由字在 [平组/仄组] 的出现情况判平/仄/两可/未录；`checkMeter` 逐字比对标准谱，按“一三五不论”通融，并专门检查孤平、三平调；押韵由韵脚众数推断韵部后逐一校验。
- 可借鉴：数字平仄谱表示法、韵书 [平, 仄] 分组结构、韵部众数推断法。
- 不足：过程式、依赖全局变量、与浏览器耦合、无对仗/拗救细分、常量散落字面量；本项目将以 TypeScript + OOP + 职责链重构。
- 许可：cope 仓库无独立 LICENSE 文件，其 `package.json` 声明为 **ISC**（宽松许可，非 GPL），复用不受许可限制；本项目仅借鉴其“思路与数据组织”、不复制源码，原因是工程层面（过程式、与浏览器耦合、无对仗/拗救细分），运行数据另采 MIT 来源，算法自行实现。

## 4. 数据源调研

韵表为基础需求（FR-A9：默认平水韵，另支持词林正韵、新韵、通韵），数据选型以“一源多韵表、MIT 可商用、含入声”为准：

- **★ charlesix59/chinese_word_rhyme（GitHub，MIT）**：推荐作为 vendored 数据源。
  - `Pingshui_Rhyme.json`（207KB）：平水韵按声部结构化（上平/下平/上声/去声/入声），入声独立保留。
  - `Cilin_Rhyme.json`（96KB）：词林正韵 19 部（平声/仄声）。
  - `Xinyun_Rhyme.json`（101KB）：中华新韵 14 韵（平/仄）。
  - `Word_Tune.json`（148KB）：字→平/仄 直接表，8232 字（含“两可”标记）。
  - 另有 `Ci_Tunes.json`（19.6MB 词谱）、`Word_Explain.json`。
- **pinyin-pro（npm，MIT，~950KB）**：拼音/声调/多音字上下文解析；仅用于显示或辅助分词，**不用于平水韵平仄判定**（入派三声）。但可为**新韵/通韵**（今音韵表）提供声调依据。
- **opencc-js（npm，MIT/Apache，~6MB）**：纯 JS 繁简转换，用于输入归一。
- **广韵声调兜底**：平水韵内置约 8232 字，生僻/异体字可能未录。以 LingDong-/cope（ISC）整理的广韵声调表（12722 字，较平水韵另增约 4940 字）作平仄兜底，平仄覆盖面扩至约 1.3 万字；仍未录者于要位给“韵书未录”提示（押韵分部仍以平水韵为准）。
- **chinese-poetry（npm，MIT，~362MB）**：全唐诗宋词语料，仅作测试夹具，不作运行时依赖。
- 其他检测器：Haorui-Jiang/pingze（JS，MIT）、odafeng/poetry-meter（Python，查平水韵判平仄，印证设计方向）；Blindinlights/PingZe（TS，无许可，不复制）。
- **缺口与风险**：**中华通韵**无现成字表，改以 pinyin-pro 依今音映射 16 韵部实现（声调定平仄）；词谱规模化数据零散；依赖字义的多音字平仄（看/过）在字符层面不可完全消歧。

## 5. 对仗检测调研

- 现状：对联“生成”研究众多（微软对联、seq2seq、九歌等），但几乎无“评分/校验既有对仗质量”的现成模型；以生成模型困惑度打分只是弱信号，不可解释、不可靠。
- JS 分词词性：**@node-rs/jieba**（npm 2.x，MIT，预编译二进制，`tag()` 输出词性）推荐；`jieba-wasm` 纯 WASM 可作浏览器回退；`nodejieba` 需本地编译（Windows 脆弱）；HanLP/LTP 无一流 JS 绑定（需 Python，弃）。
- 启发式可行性：可靠＝等长、节奏点平仄相对；中等＝分词数对齐；弱＝词性对应（jieba 为现代汉语训练，古诗多单音节，切分与词性常误）；须 LLM＝语义类工对、工/宽对、合掌、借对、依义多音消歧。
- 结论：先做启发式（等长 + 平仄相对，确定性且可解释），分词/词性作“建议”级信号，语义判断路由 LLM。

## 6. LLM 接入调研（2026-10 核验）

- 单客户端结论：Qwen（兼容模式）、DeepSeek、Kimi、OpenAI 均可由同一“OpenAI `/chat/completions` 兼容客户端”驱动（仅 base_url + model + key 不同）；**Anthropic 另作适配器**。
- 端点（示例，以各家最新官方文档为准）：

| 供应商 | base_url | 鉴权 | 模型示例 |
| --- | --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | `Authorization: Bearer` | gpt 系列 |
| 通义千问 Qwen（兼容模式） | `https://dashscope.aliyuncs.com/compatible-mode/v1`（含分区域域名） | Bearer（密钥区域绑定） | qwen-plus / qwen-max |
| DeepSeek | `https://api.deepseek.com`（另有 `/anthropic` 兼容） | Bearer | deepseek-chat 等 |
| Moonshot Kimi | `https://api.moonshot.cn/v1` | Bearer | kimi 系列 |
| Anthropic Claude | `https://api.anthropic.com/v1/messages` | `x-api-key` + `anthropic-version` | claude 系列 |

- Anthropic 差异：`/v1/messages` 端点；`x-api-key` 与 `anthropic-version` 头；`system` 为顶层参数；消息为 content blocks；流式事件格式不同。
- 结构化 JSON（SKILL 关键）：各家 `json_object` 支持较普遍，严格 `json_schema` 不一致。**可移植方案**：`response_format=json_object` + 提示内嵌 schema + 客户端 Zod 校验与失败重试；Anthropic 用 `output_config`/工具式结构化。

## 7. SKILL 调研与编写策略

- 目标：以最清晰、专业的文字告知大模型如何检测/推荐，并输出规范 JSON。
- 要点：角色设定（精于近体诗律的专家）；明确输入/输出 JSON schema；给出规则清单（平仄/粘对/对仗/工对宽对/合掌）；提供正反例（few-shot）；必要时附参考（王力《诗词格律》、搜韵网等）引导模型检索与思考。
- 组织：`skills/<技能名>/SKILL.md`，按检测类/推荐类分目录，多份独立维护。

## 8. 关键结论与选型建议

| 维度 | 选型 | 理由 |
| --- | --- | --- |
| 语言 | TypeScript | OOP、强类型 API、产出 ESM+CJS |
| 韵表 | 多韵表可切换，默认平水韵；另支持词林正韵、新韵、通韵 | 对应 FR-A9；韵表同时决定押韵分部与平仄判定 |
| 平仄/韵部数据 | vendored charlesix59 JSON（MIT） | 一源覆盖平水韵（含入声）/词林/新韵 |

| 繁简 | opencc-js | 纯 JS、输入归一 |
| 分词词性 | @node-rs/jieba（可选） | 预编译、出词性；对仗启发式用 |
| LLM | OpenAI 兼容核心 + Anthropic 适配 | 一套接口覆盖多家 |
| 结构化输出 | json_object + Zod 校验重试 | 跨供应商可移植 |
| 测试夹具 | 经典唐诗 | 真实校验 |
| 中华通韵 | pinyin-pro 今音映射 16 韵 | 无现成字表，依今音生成 |
