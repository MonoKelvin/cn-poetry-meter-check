## 1. 概述

cn-poetry-meter-check 是一个面向中国古典诗词（以唐代定型的“近体诗”为主）格律检测的 npm 算法包。它对输入诗作进行自动化格律分析，精确定位问题的位置与原因，并提供从“纯算法基础检测”到“AI 辅助高级检测与推荐”的分层能力。

核心目标：

- 以纯算法、可离线运行的方式完成基础格律检测（平仄、押韵、替/粘/对、孤平、三平调、拗句、拗救、多音字歧义）。
- 以稳定且克制的 API，为需要语义理解的能力（对仗检测、多音字消歧、各类推荐与生成）预留 AI（大模型）后端，内部实现可分级补充。
- 以模块化、职责单一、可独立维护与渐进增强的工程结构交付，并配套中文文档、测试与示例页面。

## 2. 术语表

为统一理解，先约定关键术语（详细原理见调研文档）：

| 术语 | 说明 |
| --- | --- |
| 近体诗 | 唐代定型的格律诗，含绝句、律诗，讲究平仄、押韵、粘对、对仗。 |
| 平仄 | 中古四声（平、上、去、入）归两类：平声为“平”，上去入为“仄”。平仄交替是格律基础。 |
| 平水韵 | 近体诗用韵的标准韵书，106 韵部，按平上去入分类，含“入声”。 |
| 韵表 | 判定押韵与平仄所依据的声韵标准：平水韵（默认，含入声）、词林正韵、中华新韵、中华通韵等；可切换。 |
| 韵脚 | 押韵位置的字，通常在偶数句句末；首句可入韵。 |
| 押韵 / 落韵 | 全诗韵脚须同一韵部；用到其他韵部即“落韵/出韵”。 |
| 粘 / 失粘 | 相邻两联间，下联出句第二字平仄须与上联对句第二字相同（“粘”）；违反为“失粘”。 |
| 替 / 失替 | 同一句内节奏点（二、四、六字）平仄须交替（平仄平 / 仄平仄）；违反为“失替”。 |
| 对 / 失对（平仄） | 同一联内出句与对句对应节奏点平仄须相反（“对”）；违反为“失对”。 |
| 对仗 / 不对仗 | 颔联、颈联要求出句与对句在词性、句法结构上相对、意义相关或相对；缺失即原始需求所称“失对”，见 §2.1。 |
| 孤平 | 平收句中除韵脚外仅余一个平声；典型见于五言“平平仄仄平”首字、七言“仄仄平平仄仄平”第三字误用仄声。 |
| 三平调（三平尾） | 句末三字连平，近体诗大忌；另有“三仄尾”为瑕疵。 |
| 拗句 / 拗体 | 不合常规平仄格式的句子 / 整体风格。 |
| 拗救 | 出现拗后，通过本句或对句相应位置调整平仄补救；救后视为合律，仅作提示。 |
| 多音字 | 一字多读且读音平仄不同（如“长”：cháng 平 / zhǎng 仄），可能影响合律判定。 |
| 出句 / 对句 | 一联中的上句 / 下句。 |
| 首句入韵 | 律绝首句即押韵（句末为平声韵脚）；“不入韵”则句末为仄声。 |

### 2.1 关于“失对”的术语澄清

原始需求将颔联、颈联的“对仗”缺失称为“失对”，并归入高级检测。需注意古典格律中“对”有两层含义：

- **平仄之“对”**：同一联内出句与对句，节奏点（二、四、六字）平仄应相反。违反属“失对（平仄）”，可纯算法检测，归入基础检测（FR-A4）。
- **对仗之“对”**：颔联、颈联出句与对句在词性、句法结构上相对，意义相关或相对（工对/宽对）。其缺失即原始需求所称“失对”，需词法/句法乃至语义分析，归入高级检测（FR-B1）。

本文档中，“失对（平仄）”指前者，“对仗/不对仗”指后者，以免混淆。

## 3. 范围

### 3.1 v1.0.0 范围内

- **基础检测（纯算法、离线）**：五绝、五律、七绝、七律及其平起/仄起、首句入韵/不入韵形成的标准格式；平仄、押韵、粘对、孤平、三平调/三仄尾、拗句/拗体识别、拗救识别、多音字平仄歧义警告；支持多韵表切换（默认平水韵，另含词林正韵、中华新韵、中华通韵）。
- **高级检测（API 稳定，实现可分级）**：对仗（即“失对”）检测、多音字精确消歧；提供启发式与 LLM 两档后端，内部实现可留空但契约固定。
- **推荐（API 稳定，LLM 后端）**：出律补救、对仗替换、整诗/对句/填字生成、字眼推荐。
- **通用 AI 模块**：OpenAI 兼容对话客户端 + Anthropic 适配；SKILL 装载与结构化输出解析。
- **工程交付**：示例 HTML 页、接口测试、中文 API 文档、README（中文）、MIT 许可、常规 npm 包文件、SKILL.md 文档集。

### 3.2 范围外 / 后续版本

- 词（词牌）、曲格律：预留数据结构与接口，v1.0.0 不实现检测。
- 古体诗、排律（超八句律诗）：预留。
- 本地离线大模型 / 自训练模型：原始需求明确不推荐，不纳入。
- 深度今音变读：新韵、通韵依今音，多音字今读的语境判定 v1.0.0 以字表为准，不做深度语义变读。

## 4. 用户与使用场景

典型用户：

- **诗词创作者**：边写边检测，快速定位出律字并获得补救建议。
- **学习者 / 教学者**：理解格律错误的具体原因与补救原理。
- **开发者**：将检测能力集成到编辑器、网站、小程序等，通过 API 校验。
- **内容平台**：批量校验投稿诗作的格律合规性。

关键用例：

- UC-1：对已知诗体的诗作做格律校验，获得逐字平仄、押韵、粘对结论与错误定位。
- UC-2：未指定诗体时自动识别诗体后校验。
- UC-3：对出律处给出补救建议（推荐模块）。
- UC-4：检测颔联、颈联是否对仗。
- UC-5：多音字歧义提示，并在可用 AI 时消歧。
- UC-6：按题目/韵/体裁生成或补全诗句。

## 5. 功能需求

### 5.1 FR-A 基础检测模块（P0，纯算法）

- **FR-A1 诗体识别与匹配**：按字数（五/七言）与句数（四句绝句/八句律诗）匹配诗体；支持平起/仄起、首句入韵/不入韵的标准格式；允许显式指定或自动推断诗体。
- **FR-A2 平仄检测**：逐字判定平/仄/中并与标准格式比对，遵循“一三五不论”的通融，同时保留孤平、三平调约束；对不合者给出位置与原因。
- **FR-A3 押韵检测**：自动推断全诗韵部（以韵脚众数），校验各韵脚同韵部；区分首句入韵与否；检测落韵、重韵；该押韵而未押给出错误。
- **FR-A4 替粘对检测**：检测失替（句内节奏点未交替）、失粘（联间）、失对（联内，平仄层面）。
- **FR-A5 孤平 / 三平调 / 三仄尾检测**。
- **FR-A6 拗句 / 拗体识别**：识别常见拗句句型并归类。
- **FR-A7 拗救识别**：识别本句自救（如孤平拗救）与对句相救；救后标记为“合律（已拗救）”，作为提示而非错误。
- **FR-A8 多音字平仄歧义**：当字存在多个平仄读音且影响合律时，输出警告，列出各读音对应韵部/平仄及由此导致的合律/出律差异（示例“长”）。
- **FR-A9 韵表支持**：押韵与平仄判定均以所选韵表为准，默认平水韵（中古音，入声为仄）；另支持词林正韵、中华新韵、中华通韵等，可切换。注意切换韵表会同时改变押韵分部与平仄归类（今音韵表无入声）。

### 5.2 FR-B 高级检测模块（P1，API 稳定、实现可分级）

- **FR-B1 对仗检测**（即原始需求“失对”）：检测颔联、颈联是否对仗（词性相对、结构相对、平仄相对）。提供两档后端：启发式（分词 + 词性 + 平仄，输出可信度与问题点）与 LLM（SKILL 驱动）。内部实现可留空，但对外 API 固定。调研结论：平仄相对与等长可较可靠地启发式判定，词性/语义层面的工对、合掌等须由 LLM 处理。
- **FR-B2 多音字精确消歧**：结合上下文词语确定该字确切韵部/平仄，消解 FR-A8 的歧义警告；以 LLM 或词表为后端，API 固定。

### 5.3 FR-C 推荐模块（P2，LLM 后端、API 稳定）

对应原始需求六项：

- **FR-C1 出律补救推荐**：对出律字给出改平仄、换字且保证押韵的方案。
- **FR-C2 对仗替换推荐**：对不对仗处给出合理对仗替换。
- **FR-C3 自动成诗**：按题目、体裁、题材、押韵自动完成诗体书写。
- **FR-C4 补句**：据出句补对句、据对句补出句（结合全诗）。
- **FR-C5 自动填字**：结合全诗推荐填字。
- **FR-C6 字眼推荐**：五言第三字、七言第五字须“响”，对已有诗句斟酌字眼下字。

### 5.4 FR-D 通用 AI 模块（P1，业务无关）

- **FR-D1 统一对话客户端**：以 OpenAI 兼容 `/chat/completions` 为核心（覆盖 Qwen 兼容模式、DeepSeek、Kimi、OpenAI），Anthropic Messages 以适配器接入；可配置 api_key、base_url、model_id、温度、超时等。
- **FR-D2 SKILL 装载**：从 `skills/` 目录加载 SKILL.md，组装系统/技能提示。
- **FR-D3 结构化输出**：约定并解析 JSON 结果（检测类/推荐类），容错解析并在失败时重试。
- **FR-D4 业务无关**：AI 模块不含诗词业务逻辑，仅提供对话、提示组装、结构化解析等基础能力，供上层调用。

### 5.5 FR-E 示例页面（P0 基础 / P1 高级）

单页 HTML + app.js + app.css：输入诗作、选择或自动识别诗体、展示逐字平仄与错误标注、押韵与对仗结论；在配置 API Key 后可体验高级检测与推荐。

### 5.6 FR-F 工程交付物

- 接口测试：覆盖基础检测核心用例，以经典唐诗为夹具。
- 中文 API 文档（docs/）、README.md（中文）、LICENSE（MIT）、package.json 等常规文件。
- SKILL.md 文档集：检测类、推荐类，按目录区分。

## 6. 输出格式需求

检测结果须为结构化、可序列化为 JSON 的对象：

- **整体结果**：诗体、所用韵表、推断韵部、是否通过、问题统计。
- **逐项问题**：位置（第几联、出/对句、第几字、字符）、级别（error / warn / info）、类别（平仄 / 押韵 / 失替 / 失粘 / 失对 / 孤平 / 三平调 / 拗救 / 多音字 等）、中文原因描述、可选修改建议。

LLM 相关输出：

- **检测类 SKILL**：按 SKILL 规范输出问题位置 + 原因（JSON）。
- **推荐类 SKILL**：输出推荐文本（可多个则为列表）+ 推荐理由。
- 为跨供应商可移植，统一以 `response_format: json_object` + 提示内嵌 schema + 客户端（Zod）校验与重试的方式获取结构化结果。

## 7. 非功能需求

- **NFR-1 模块化**：采用职责链；每种检测为最小独立单元，可独立维护与升级。
- **NFR-2 离线性**：基础检测零网络依赖；AI 能力为可选增强。
- **NFR-3 可扩展**：新增诗体、检测器、韵表、LLM 供应商的接入成本低。
- **NFR-4 跨环境**：Node 与浏览器均可用（示例页可直接运行）；发布 ESM + CJS 双格式。
- **NFR-5 性能**：单首诗基础检测应在毫秒级完成。
- **NFR-6 可配置**：韵表（默认平水韵，支持切换词林正韵/新韵/通韵）、严格度、拗救宽松度等以常量/配置集中管理，不写死魔法值。
- **NFR-7 国际化**：文档与面向用户的错误描述用中文；代码标识符用英文。
- **NFR-8 许可**：MIT。
- **NFR-9 API 克制**：对外导出“少而全”，以门面/桥接封装内部复杂度。
- **NFR-10 安全**：API Key 由调用方注入，不硬编码、不随包发布；仅在显式配置 AI 后发生网络请求。

## 8. 约束与假设

- 默认以平水韵为准（近体诗传统）；今音仅作可选增强。
- 平仄判定依赖“字→韵部/声调”数据完整性；未收录字给出“韵书未录”警告而非错误。
- 多音字语义消歧、对仗语义判断超出纯算法能力，需 NLP/LLM，故相应内部实现可留空但 API 固定。
- 输入可为简体或繁体中文，内部统一处理（繁简转换 / 按韵表归一）。

## 9. 验收标准

- 对经典五/七言绝句与律诗样本，基础检测在平仄、押韵、粘对结论上与权威工具（诗词吾爱、我爱诗词）抽样核对高度一致。
- 正确识别首句入韵/不入韵、平起/仄起格式。
- 正确识别典型孤平、三平调、失替、失粘、失对（平仄）、拗救案例。
- 对典型多音字（如“长、看、过、听、思”等）给出平仄歧义警告。
- 正确支持韵表切换：以平水韵、中华新韵分别校验同一首诗，平仄与押韵结论随韵表变化且各自自洽。
- 高级/推荐模块提供契约稳定、可调用的 API；即使内部为桩实现，也返回规范结构或明确的“未实现”标识。
- 测试通过；文档齐备；示例页可供手动验证。
